# Karmik — UI Specification

## Overview

Karmik has three UI surfaces:
1. **Floating Overlay** — always-accessible, sits over any app (default mode)
2. **Main App** — full-screen experience for configuration and deep interaction
3. **Launcher Mode** — optional home screen replacement

## Surface 1: Floating Overlay

The overlay is a `SYSTEM_ALERT_WINDOW` floating window. It persists across all apps and is the
primary entry point for quick interactions.

### States

```
IDLE                PEEK                  EXPANDED
─────────          ─────────────────     ─────────────────────────
   ●               ●  1 new result        ┌──────────────────────┐
 (bubble)          ●──→ [result card]     │ 🔍 Ask or speak...   │
                                          │──────────────────────│
                                          │ [Agent Tabs]         │
                                          │  Aria  Work  +       │
                                          │──────────────────────│
                                          │ [Message stream]     │
                                          │                      │
                                          │──────────────────────│
                                          │ 🎤  [Send]  [Tools]  │
                                          └──────────────────────┘
```

### Bubble (Idle State)
- 56dp circle, floating at screen edge (user can drag to any edge)
- Avatar of the currently-active agent (emoji or image)
- Pulsing animation when a background agent has a new result
- Badge count for pending results
- Tap → expand to Peek or Full
- Long press → quick-action menu (switch agent, open app, dismiss)

### Peek State
- Result card slides out from the bubble (like a notification)
- Shows: agent name, result summary (2 lines max), action buttons
- Tap the card → expand to Full
- Swipe right → dismiss card
- Card auto-dismisses after 8 seconds if no interaction

### Expanded State (Compact Chat Panel)
- Height: ~60% of screen, anchored to the bubble edge
- Tabs for switching between active agents (max 3 tabs)
- Input field with mic button (push-to-talk)
- Streaming response appears token by token
- Tool call events shown inline: "Checking calendar... ✓"
- [Tools] button opens a quick-pick of the active agent's allowed tools
- Tap outside → collapse to Peek, then Idle

### Co-pilot Action Cards

When an agent (in Co-pilot mode) proposes an action, a card appears in the expanded view:

```
┌─────────────────────────────────────────────────────┐
│ 📤 Proposed action                                   │
│ Send SMS to Alex Chen:                               │
│ "I'll send you that article tomorrow morning"        │
│                                                      │
│ [Approve ✓]    [Edit ✗]    [Skip →]   [Cancel ✕]   │
└─────────────────────────────────────────────────────┘
```

**File write diff view**: When the proposed action is `files.write` on an existing file,
the action card expands to show a unified diff instead of the raw content:

```
┌─────────────────────────────────────────────────────┐
│ 📝 Proposed file change                              │
│ ~/Documents/notes.md                                 │
│──────────────────────────────────────────────────── │
│  ## Meeting notes                                    │
│ - Date: June 14                                      │
│ + Date: June 14  ·  Attendees: Alex, Priya, Sam      │
│ + Action items:                                      │
│ + - Follow up on Q2 numbers by Friday                │
│                                                      │
│ [Approve ✓]    [Edit]    [Skip →]   [Cancel ✕]      │
└─────────────────────────────────────────────────────┘
```

- Red lines (−) show content being removed; green lines (+) show additions
- "Edit" opens the full file in a bottom-sheet editor with the diff applied, allowing
  the user to modify before approving
- For new files (`files.write` to a path that doesn't exist), shows full content preview
  instead of a diff

## Surface 2: Main App

Full-screen Flutter app. Opened by tapping the overlay's "Open" button or the app icon.

### Navigation Structure

```
Bottom navigation (4 tabs):
  🏠 Home    💬 Chats    🤖 Agents    ⚙️ Settings
```

### Home Tab

Dashboard view, shows:
- Active agent status cards (what each background agent is doing right now)
- Recent activity feed (tool calls, task captures, briefings from last 24h)
- Quick-launch buttons for pinned agents
- Storage indicator (model sizes, memory database size)

### Chats Tab

- List of all agent conversations (grouped by agent, sorted by recency)
- Each item: agent avatar, last message preview, timestamp, unread indicator
- Tap → opens the full chat view for that agent

**Chat View** (per agent):
```
┌────────────────────────────────┐
│ ← Aria                    ···  │
│──────────────────────────────  │
│                  User message  │
│                           →→→  │
│                                │
│  ←←← Aria message              │
│  with streaming tokens         │
│                                │
│  ┌──────────────────────────┐  │
│  │ Tool: calendar.list_events│  │
│  │ ✓ Found 3 events today   │  │
│  └──────────────────────────┘  │
│                                │
│──────────────────────────────  │
│ 🎤  Type or speak...  [Send]  │
└────────────────────────────────┘
```

The `···` menu: model info, clear conversation, export, agent settings.

Tool call events are collapsible: tap to expand and see full input/output.

**Context window indicator** (in the chat header, right of the agent name):
```
← Aria  [████░░░░ 42%]  ···
```
The bar fills as the context window is consumed. Tapping it shows: "2,841 / 8,192 tokens used."
Turns amber at 70%, red at 85% (approaching compression threshold).

**Session resume**: When the user returns to a conversation that was last active > 30 minutes
ago, a banner offers to reload the prior context:
```
┌──────────────────────────────────────────┐
│ ↩ Resume from last session? (2h ago)     │
│ [Load history]          [Start fresh]    │
└──────────────────────────────────────────┘
```
"Load history" loads the most-recent turn window from Tier 2 into the ephemeral context.
"Start fresh" begins a new conversation (old history remains in Tier 2, accessible via search).

**Per-message cost annotation** (remote providers only, toggled in Settings → Appearance):
```
  ←←← Aria message...

  ↳ 342 in · 89 out · $0.001
```

**Rollback UI**: Each assistant message bubble has a `···` overflow with "Roll back to here".
Shows a confirmation sheet: "Remove the [N] messages after this point?"

### Chat Input — @ Mentions

Type `@` in the chat input to open a context picker. Attaches context objects to the
current message without pasting raw text.

```
@ picker (appears above keyboard when @ is typed):
┌──────────────────────────────────────────────┐
│  @  Search...                                │
│──────────────────────────────────────────────│
│  📁 file         Attach a file from storage  │
│  🧠 memory       Search your long-term memory│
│  ✅ task         Attach an open task         │
│  📅 calendar     Attach a calendar event     │
│  👤 contact      Attach a contact            │
│  🔔 notification Attach a recent notification│
│  🖼 image        Attach a photo/screenshot   │
└──────────────────────────────────────────────┘
```

Each `@mention` renders as a chip in the input field:
```
[ @file: budget.pdf ] [ @task: Send Alex the article ]  Type here...
```

On send, mentioned objects are serialized and appended to the user message as structured
context blocks. The model sees them as formatted text (file contents, task JSON, etc.) after
the user's message.

**`@image`**: Opens the system photo picker. Selected image is encoded as base64 and included
in the message content. Only enabled when the loaded model has `supportsVision: true`; the
button is greyed out otherwise with tooltip: "Switch to a vision-capable model to attach images."

### Chat Input — Slash Commands

Type `/` at the start of the input to open the command palette.

```
/ Command palette:
┌──────────────────────────────────────────────┐
│  /  Search commands...                       │
│──────────────────────────────────────────────│
│  /clear     Clear this conversation          │
│  /compact   Compress context now             │
│  /cost      Show token usage & cost          │
│  /think     Toggle extended thinking         │
│  /model     Switch model                     │
│  /mode      Switch orchestration mode        │
│  /tools     List active tools                │
│  /memory    Search memories                  │
│  /checkpoint Save a named rollback point     │
│  /loop N    Repeat last message every N min  │
│  /export    Export conversation as markdown  │
└──────────────────────────────────────────────┘
```

**Command details**:

| Command | Effect |
|---|---|
| `/clear` | Clears ephemeral context (prompts confirmation); Tier 2 history preserved |
| `/compact` | Manually triggers rolling context compression immediately |
| `/cost` | Inline response: "Session: 4,123 in / 892 out · $0.02 total" |
| `/think [low\|med\|high]` | Toggles extended thinking; `low`=1K tokens, `med`=4K, `high`=8K |
| `/model [name]` | Opens model picker; `/model gemma` fuzzy-matches downloaded models |
| `/mode [react\|plan\|auto\|copilot]` | Switches orchestration mode for this session only |
| `/tools` | Lists all tools this agent is allowed to use; tapping a tool shows its schema |
| `/memory [query]` | Searches memories; results shown inline, tappable to pin to context |
| `/checkpoint [label]` | Saves a named checkpoint; returns checkpoint ID |
| `/loop [N]` | Resends the last user message every N minutes; `/loop stop` cancels |
| `/export` | Exports conversation as Markdown; shares via Android share sheet |

### Chat Input — Image Attachment (explicit button)

A `+` button left of the text field opens an attachment sheet (separate from `@image`):

```
┌──────────────────────┐
│  📷 Camera           │
│  🖼 Photo library    │
│  📁 Files            │
│  📋 Paste from clipboard│
└──────────────────────┘
```

Images are shown as thumbnails in the input area before sending. Multiple images per message
are supported if the model supports multi-image input.

### Agent Detail / Settings — Pinned Context

The "Persona" section of Agent Settings gains a "Pinned context" field below the system prompt:

```
Persona
  System prompt: [_____________________]
                 [_____________________]

  Pinned context (always included — like a .cursorrules file):
  [_____________________]
  [_____________________]
  2,000 character limit · 142 tokens estimated
```

This text is injected after the system prompt in every conversation with this agent.

### Agents Tab

**Agent List**:
- Cards for each named agent: avatar, name, description, last active
- Tap → Agent Detail screen
- [+] button → Create new agent (wizard or quick-create)

**Agent Detail / Settings**:
```
Sections:
  Identity      — name, avatar, description
  Persona       — system prompt editor (markdown, with templates)
                  + Pinned context field (always-include, like .cursorrules)
  Model         — model picker (shows downloaded models + remote options)
                  + Smart routing toggle
                  + Extended thinking toggle + budget slider
  Mode          — orchestration mode selector (ReAct | Plan-Execute | Autopilot | Co-pilot)
  Tools         — toggle switches for each tool category (incl. code.run)
  Plugins       — list of active plugins for this agent
  Memory        — memory config, retention settings
  Triggers      — background trigger configuration
  Danger Zone   — delete agent, clear memory
```

**Agent Creation Wizard**:
1. Pick a starting point: blank | clone existing | from template library
2. Give it a name and emoji
3. Select purpose from presets (or write custom system prompt)
4. Pick model (recommended based on device)
5. Choose tools (checkboxes per category)
6. Done — opens agent chat immediately

### Settings Tab

Sections:
  Models          — Model Manager (browse, download, active model)
  Providers       — Remote provider configuration (API keys)
  Plugins         — Global plugin manager (install, enable/disable)
  Background      — Background service toggle, battery settings
  Privacy         — Audit log viewer, data export, delete all data
  Appearance      — Theme (dark/light/system), overlay position

## Surface 4: Android Share Sheet Integration

Karmik registers as a share target for common content types. When another app (Chrome,
WhatsApp, Files, Gallery, etc.) shares content using the Android share sheet, Karmik
appears as a share destination.

**Registered MIME types**:
| MIME type | Source apps | Karmik behavior |
|---|---|---|
| `text/plain` | Browser, WhatsApp, Notes | Opens overlay with text pre-attached as `@text` context |
| `text/html` | Browser "share page" | Strips to text, attaches as `@webpage` with title + URL |
| `image/*` | Gallery, Camera, Screenshots | Attaches as `@image`; vision model selected if needed |
| `application/pdf` | Files, Drive | Extracts text via on-device PDF parser, attaches as `@file` |
| `*/*` (files) | Files | Reads file content if text-based, else attaches as file path reference |

**AndroidManifest intent filter**:
```xml
<activity android:name=".ShareReceiverActivity">
  <intent-filter>
    <action android:name="android.intent.action.SEND" />
    <category android:name="android.intent.category.DEFAULT" />
    <data android:mimeType="text/*" />
    <data android:mimeType="image/*" />
    <data android:mimeType="application/pdf" />
  </intent-filter>
</activity>
```

**Share flow UX**:
```
User shares text from Chrome
        │
        ▼
Karmik overlay opens (or app opens if overlay not enabled)
        │
        ▼
┌────────────────────────────────────────┐
│ 🔗 Shared from Chrome                  │
│ "The best productivity apps of 2026"   │
│ https://example.com/article            │
│                                        │
│ Send to:  [Aria ▼]  (agent picker)    │
│                                        │
│ [ What do you want me to do with this?]│
│                                        │
│ Quick actions:                         │
│  [Summarize]  [Save as memory]  [Task] │
└────────────────────────────────────────┘
```

- Agent picker defaults to the user's last-used agent
- Quick action buttons pre-fill the message input (user can edit before sending)
- "Save as memory" bypasses chat entirely: content is embedded and stored in Tier 3 immediately

**Direct-share targets** (Android direct share — shows agent avatars in the share sheet):
Each named agent is registered as a direct-share target so the user can share content
directly to "Aria" or "Work" without the intermediate agent picker screen.

## Theming

- Dark mode by default (OLED-friendly, true black)
- Light mode option
- Follows system theme by default (Auto)
- Accent color: user-selectable (default: deep violet — karma purple)
- Overlay transparency: adjustable (70–100%)
- Text size: follows system accessibility settings

## Accessibility

- All interactive elements have content descriptions
- Minimum touch target: 48dp
- Screen reader (TalkBack) compatible
- High contrast mode support
- No animations by default when "Reduce motion" is enabled in Android settings
